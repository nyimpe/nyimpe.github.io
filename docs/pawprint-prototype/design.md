# Paw Valley (가제) — 기획 및 기술 설계

## 1. 컨셉 요약

- 스타듀밸리 스타일의 생활 시뮬레이션을 뼈대로 하되, **던전 탐험과 아이템 수집**을 핵심 루프로 둔다.
- NPC 상호작용·스토리는 최소화한다. 마을에는 대화 없는 상점 표지판 하나만 둔다.
- 주인공은 **강아지 또는 고양이**(인간형, 두 발로 걷는 수인) 중 선택한다.
- 2D 픽셀아트(16×16 타일, 정수 배율 스케일링).
- 브라우저 접속 + 모바일 터치 대응. 추후 온라인 실시간 멀티플레이 확장을 염두에 둔다.

## 2. 핵심 루프

```
마을에서 채집·낚시 → 집에서 요리(버프) → 던전 진입 → 전투·채광·보물상자
   ↑                                                      │
   └──── 재료·골드로 가구 제작(하우징), 포션 구매 ◄──────────┘
```

| 시스템 | 프로토타입 범위 | 이후 확장 |
|---|---|---|
| 채집 | 나무·베리·돌·버섯, 시간 경과 후 재생 | 도구 등급, 계절별 자원 |
| 낚시 | 타이밍 바 미니게임, 3종 물고기 | 낚시대 등급, 지역별 어종 |
| 요리 | 화로에서 4종 레시피, 즉시 회복 + 시간제 버프 1개 | 레시피 해금, 버프 중첩 규칙 |
| 하우징 | 작업대에서 가구 제작, 집 안 타일에 배치/회수 | 집 확장, 벽지·바닥, 외부 농장 |
| 던전 | 층마다 랜덤 생성(방+복도), 슬라임·박쥐, 광석, 보물상자, 아래층 계단 | 보스층, 함정, 희귀 드롭 테이블 |
| 전투 | 방향 근접 공격, 접촉 피해, 피격 무적 시간, 넉백 | 무기 종류, 스킬, 원거리 |
| 저장 | localStorage (침대에서 잠자기 + 맵 이동 시 자동) | 서버 저장(멀티 전환 시 필수) |

## 3. 조작

| 동작 | PC | 모바일 |
|---|---|---|
| 이동 | WASD / 방향키 | 왼쪽 가상 스틱 |
| 행동(채집·낚시·대화·설치) | Space / Z / Enter | A 버튼 |
| 공격 | X / J | B 버튼 |
| 가방 | I | 가방 버튼 |
| 닫기 | Esc | 패널의 닫기 |

## 4. 기술 설계

### 4.1 프로토타입 (현재)

- **의존성 없는 단일 HTML 파일** `prototype/index.html`. 빌드 없이 더블클릭 또는 정적 호스팅으로 실행.
- Canvas 2D, `imageSmoothingEnabled=false`. 내부 해상도를 화면 크기 ÷ 정수 배율로 잡아 세로/가로 어느 쪽이든 픽셀이 깨지지 않는다.
- 모든 스프라이트·타일은 코드로 생성(문자열 픽셀맵 + 절차적 타일). 외부 에셋 없이 동작하고, 나중에 PNG 아틀라스로 교체하기 쉽다.
- UI(가방·요리·제작·상점)는 DOM 오버레이로 만들어 터치 입력과 한글 텍스트 처리가 쉽다.

### 4.2 정식 개발 권장 스택

| 영역 | 권장 | 이유 |
|---|---|---|
| 클라이언트 | TypeScript + **Phaser 3** (또는 PixiJS) | 타일맵(Tiled 포맷), 아틀라스, 카메라, 입력이 내장. 픽셀아트 설정이 간단 |
| 맵 제작 | Tiled | Phaser가 JSON을 바로 읽음. 던전은 코드로 생성 |
| 번들 | Vite | 빠른 개발 서버, 모바일 기기에서 LAN 테스트 용이 |
| 멀티플레이 | **Colyseus** (Node.js, WebSocket) | 룸·상태 동기화 기본 제공. 방 단위 소규모 협동에 적합 |
| 저장/계정 | Supabase 또는 자체 Postgres | 멀티로 가면 클라이언트 저장은 폐기 |
| 배포 | 정적 호스팅(Cloudflare Pages 등) + 게임 서버(Fly.io 등) | |

### 4.3 멀티플레이를 대비한 구조 원칙

프로토타입에서도 아래 원칙을 지켜 두면 서버 전환 비용이 줄어든다.

1. **상태와 렌더링 분리**: 플레이어·적·드롭·맵 변화는 모두 하나의 `S` 상태 객체에 있고, 렌더 함수는 그것을 읽기만 한다. 서버 권한 모델로 옮길 때 이 상태가 그대로 "서버가 들고 있는 룸 상태"가 된다.
2. **입력은 의도만 전달**: 이동 벡터, 행동 버튼, 공격 버튼. 서버에서는 이 입력을 받아 같은 시뮬레이션 코드를 실행한다.
3. **결정적 던전 생성**: 시드 기반 생성으로 바꾸면 서버가 시드만 보내고 모든 클라이언트가 같은 층을 만든다.
4. **마을은 공유 공간, 집은 개인 공간**: 집(하우징)은 소유자만 수정 가능한 인스턴스로 설계한다.
