# 묘수 화면 시안

`/posts/turn-based-roguelike-overview/`(턴제 로그라이크 기획 — 묘수)에 실린 화면 시안 세 장의 출처와 다시 만드는 법이다.
지금 게시된 그림은 Pillow로 직접 찍은 픽셀 목업이다. `prompts.json`으로 Codex에서 AI 그림을 새로 만들어 바꿀 수 있다.
화면 속 숫자와 배치는 기획 글의 규칙을 보여 주기 위한 예시이며, 실제 게임 화면이 아니다.

| 화면 | 목업 스크립트 | 게시 이미지 | 글에서 쓰는 곳 |
| --- | --- | --- | --- |
| 재주 고르기 | `pickscreen.py` | `public/images/turn-based-roguelike-screens/01-pick-skill.webp` | `#skills` 절의 첫 그림 |
| 강 동네 지도 | `mapscreen.py` | `public/images/turn-based-roguelike-screens/02-river-map.webp` | `#run` 절의 “지도와 칸” |
| 강 우두머리전 | `battle.py` | `public/images/turn-based-roguelike-screens/03-river-leader.webp` | 글 맨 위 그림, `og:image`. `#turn-order`와 “강 우두머리전 예시”가 이 그림을 가리킨다 |

## Pillow 목업 다시 만들기

320×180 캔버스에 픽셀을 직접 그린 뒤 4배로 키우고, 글자만 최종 해상도(1280×720)에서 Apple SD Gothic Neo로 얹었다.
주인공 나비는 `public/cat.png`를 줄여 팔레트에 맞춘 것이다.

```sh
cd docs/turn-based-roguelike-screens
python3 battle.py /tmp/battle.png
python3 mapscreen.py /tmp/map.png
python3 pickscreen.py /tmp/pick.png
```

PNG를 손실 없는 WebP로 저장해 게시 이미지를 바꾼다. 픽셀 경계가 뭉개지지 않도록 `npm run optimize:images`의 손실 압축은 거치지 않았다.
macOS의 `/System/Library/Fonts/AppleSDGothicNeo.ttc`와 Pillow 11 이상이 필요하다.

## Codex로 새로 그리기

세 단계다. 1단계만 Codex 내장 이미지 생성(`image_gen`)을 쓰고, 2·3단계는 Pillow와 글 수정이다.

### 1. 그림 생성

`prompts.json`에 세 화면의 프롬프트가 있다. 형식은 예전 어울 기획의 `art-*.json`과 같다.
이미지 모델이 한글을 자주 깨뜨리므로 **글자·숫자 없이 그림과 빈 UI 틀만** 그리게 했다.
꼬리 셋을 모은 판의 장면이라 나비는 꼬리가 세 개다.

Codex에 이렇게 요청한다.

```text
docs/turn-based-roguelike-screens/README.md를 읽고 "1. 그림 생성"만 해 줘.
prompts.json의 세 프롬프트를 고치지 말고 그대로 써서 내장 image_gen을 실행하고,
결과는 각 항목의 sourcePath에 PNG로 저장해 줘. logs/turn-based-roguelike-screens/ 폴더가 없으면 만들어.
1536x864를 그대로 만들 수 없으면 가장 가까운 가로 크기로 만들고, 자르거나 늘리지 마.
README의 확인 목록으로 세 장을 직접 보고, 어긋난 장은 같은 프롬프트로 다시 만들어.
끝나면 logs/turn-based-roguelike-screens/generation.json에 장마다 날짜, 도구, 크기, 시도 횟수, SHA-256, 확인 결과를 적어 줘.
게시나 커밋은 하지 마.
```

원본은 gitignore된 `logs/turn-based-roguelike-screens/`에만 남는다.

**확인 목록**

- 글자, 숫자, 글씨처럼 보이는 자국이 어디에도 없다. 말풍선, 카드, 버튼, 막대는 비어 있다.
- 무섭거나 다치는 장면이 없다. 밝고 장난스럽다.
- UI가 모두 화면 안에 들어 있고, 제목·로고·워터마크가 없다.
- 01 재주 고르기: 카드는 정확히 세 장이고 가운데 카드만 금테다. 왼쪽부터 개 한 쌍, 푸른 말, 거북이다. 김서방은 파란 도깨비이고 웃으며 손을 흔든다.
- 02 강 동네 지도: 칸이 아래부터 1, 3, 2, 3, 2, 3개이고 맨 위에 큰 우두머리 칸 하나가 있다. 지나온 길은 주황 실선, 칸 하나를 건너뛰는 파란 점선 호가 있다. 지도 위 캐릭터는 고양이 얼굴 표식 하나뿐이다.
- 03 강 우두머리전: 고양이 하나와 물고기 하나다. 고양이는 꼬리가 셋이다. 순서 막대는 여덟 칸이고 고양이, 물고기, 고양이, 물고기, 고양이, 물고기, 고양이, 고양이 순서다. 기술 버튼은 넷이고 셋째는 회색, 넷째는 자물쇠다.

같은 프롬프트로 세 번 넘게 어긋나면 멈추고 알린다. 프롬프트를 고칠 때는 `prompts.json`도 함께 고친다.

### 3. 바꿔 끼우기

- 한글을 얹은 PNG를 WebP로 저장해 각 항목의 `replaces` 경로를 덮어쓴다. 파일 이름이 같으니 글의 `src`와 `og:image`는 그대로 둔다.
- 크기는 원본 그대로(1536×864) 둔다. 글의 `<img>`에 적힌 `width="1280" height="720"`을 실제 크기로 고친다.
- AI 그림은 손실 WebP(품질 85 안팎)로 저장해도 된다. 한 장이 500KB를 넘지 않게 한다.
- `posts/turn-based-roguelike-overview/index.html`에서 세 그림의 `alt`와 `figcaption`을 새 그림에 맞게 고친다. 지금 문구는 Pillow 목업을 묘사한다.
- 같은 글의 “강 우두머리전 예시” 절(나비 속도 12 → 느림 10, 돌진 쉬는 턴 2, 비 부르기 다음 물살 18, 막대 순서)이 새 03 그림과 맞는지 본다.
- 같은 글의 “만든 것과 남은 것” 절에서 화면 시안 설명(“이미지 생성 도구 없이 … 코드로 픽셀을 찍고”)을 AI 생성과 한글 얹기로 바꾼다.
- 이 README의 맨 위 설명과 표에 생성 날짜와 도구를 적는다. Pillow 목업 스크립트는 지우지 않는다.
- `npm run build`가 되는지, 글에서 세 그림이 제대로 뜨는지 확인한다.
