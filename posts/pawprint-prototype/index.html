본문으로 이동

작은 발자국 · 브라우저 시제품

2026.10.23

생활형 던전 RPG 기획의 첫 시제품 · 단일 HTML · PC 키보드와 휴대폰 터치 · 싱글플레이

강아지 또는 고양이를 골라 마을에서 채집하고 낚시하고, 집에서 요리해 버프를 받고, 가구를 만들어 놓고, 던전에 내려가 광석과 보물을 모아 오는 한 바퀴를 브라우저에서 직접 돌려 볼 수 있다.

같은 날 쓴 작은 발자국 — 생활형 던전 RPG 기획이 "무엇을 만들 것인가"라면, 이 글은 "그 루프가 손에 잡히는가"를 확인하기 위한 첫 시제품이다. 기획안의 일곱 줄 요구사항을 그대로 받았다. 브라우저 접속과 모바일 대응, 스타듀밸리 뼈대에 던전과 수집 강조, NPC·스토리 축소, 하우징·채집·낚시·요리(버프), 2D 픽셀아트, 추후 실시간 멀티플레이, 강아지 또는 고양이 주인공.

그림은 전부 코드로 찍은 임시 픽셀아트이고 수치는 재미 검증 전 가설이다. 외부 라이브러리와 에셋 없이 파일 하나로 돌아간다.

01. 바로 플레이

PC는 WASD 또는 방향키로 움직이고 Space/Z로 행동(채집·낚시·설치·대화 없는 상점), X/J로 공격, I로 가방을 연다. 휴대폰은 왼쪽 스틱으로 이동하고 A가 행동, B가 공격이다. 바라보는 칸에 흰 테두리가 뜨면 아래 안내문이 무엇을 할 수 있는지 알려 준다.

🐾

세로 휴대폰 화면 크기의 틀 안에서 실행된다. 저장은 이 브라우저에만 남는다.

전체 화면으로 열기 → ← 전체 글 목록

휴대폰에서는 전체 화면 링크로 여는 편이 편하다. 침대에서 자거나 맵을 옮길 때 브라우저 저장소에 저장되며, 타이틀 화면의 "이어하기"로 돌아온다.

02. 한 바퀴의 흐름

  1. 1 · 마을나무·베리·돌·버섯을 모으고 연못에서 낚시한다. 캔 자원은 시간이 지나면 다시 자란다.
  2. 2 · 집화로에서 요리해 체력과 시간제 버프를 얻고, 작업대에서 가구를 만들어 바닥에 놓는다.
  3. 3 · 던전층마다 새로 생기는 방과 복도. 슬라임·박쥐와 싸우고 광맥과 보물상자를 턴 뒤 계단으로 내려간다.
  4. 4 · 귀환사다리로 마을에 돌아와 상점 표지판에서 팔고 포션을 산다. 쓰러지면 집에서 깨어나고 골드의 20%를 잃는다.

기획안이 말한 "이번에 무엇을 가져올까, 어디까지 들어갈까, 가져온 것을 어디에 쓸까"를 가장 짧은 경로로 체험하도록 만들었다. 하루 마감, 에너지, 계절, NPC 대화는 일부러 뺐다. 상점도 사람이 아니라 표지판이다.

03. 넣은 시스템과 범위

시스템시제품에 들어간 것다음에 붙일 것
주인공타이틀에서 고양이 또는 강아지 선택. 두 발로 걷는 수인형 16×16 스프라이트, 네 방향과 2프레임 걷기.털색·이름, 실제 도트 에셋, 공격·낚시 동작.
채집나무(목재), 베리 덤불, 돌(가끔 철), 버섯. 캐면 그루터기·빈 덤불로 바뀌고 45~90초 뒤 복구.도구 등급, 지역·계절별 자원.
낚시물가에서 찌 던지기 → 입질 신호 1.1초 안에 A → 바를 물고기 높이에 맞추는 미니게임. 붕어·잉어·황금잉어.낚싯대 등급, 어종별 움직임 패턴, 도감.
요리·버프화로 레시피 4종. 즉시 회복과 함께 최대 HP·공격력·이동속도 버프가 90~180초 지속. 버프는 한 번에 하나.레시피 해금, 버프 중첩 규칙, 재료 품질.
하우징작업대에서 가구 5종 제작(의자·테이블·러그·화분·램프). 가방에서 손에 들고 집 바닥에 설치, 다시 회수. 저장됨.집 확장, 벽지·바닥, 수집품 전시 선반.
던전40×40 격자에 방 7개를 뚫고 복도로 잇는 랜덤 생성. 광맥(철·보석), 보물상자, 던전 버섯, 아래층 계단, 마을로 가는 사다리. 층이 깊을수록 적이 강해진다.시드 고정, 보스층, 함정, 드롭 테이블.
전투바라보는 방향 근접 공격, 접촉 피해, 피격 무적 0.8초, 넉백. 슬라임은 깡충 뛰며 추적, 박쥐(2층부터)는 흔들리며 빠르게 접근.무기 종류, 공격 예고, 회피.
경제상점 표지판에서 재료·물고기 판매, 회복 포션 구매. 보물상자와 적이 골드를 준다.장비 구매, 가격 조정.
저장브라우저 localStorage. 침대에서 자거나 맵을 옮길 때 저장, 타이틀에서 이어하기.서버 저장(멀티 전환 시 필수).
모바일화면 크기에 맞춰 정수 배율(2~6배)을 고르고 세로·가로 모두 내부 해상도를 다시 잡는다. 터치 기기에서만 스틱과 A·B 버튼 표시.실제 기기 입력 지연·성능 측정.

04. 화면

네 장 모두 시제품의 실제 캔버스 화면이다. 스프라이트와 타일은 문자열 픽셀맵과 사각형 그리기로 만든 임시 그림이며, 정식 에셋으로 교체할 대상이다.

05. 구조와 기술 선택

시제품은 의존성 없는 HTML 파일 하나다. 빌드 없이 열리고, 같은 와이파이의 휴대폰에서 바로 테스트할 수 있다. 캔버스 2D에 imageSmoothingEnabled=false를 주고, 화면 크기를 정수 배율로 나눈 내부 해상도에 그린 뒤 CSS로 키워 픽셀이 뭉개지지 않게 했다. 가방·요리·제작·상점 창은 DOM으로 만들어 한글과 터치 처리를 브라우저에 맡겼다.

멀티플레이를 대비해 지킨 원칙은 셋이다. 플레이어·적·드롭·맵 변화는 모두 하나의 상태 객체에 두고 렌더 함수는 읽기만 한다. 입력은 이동 벡터와 행동·공격 버튼이라는 "의도"만 넘긴다. 던전 생성은 시드 기반으로 바꾸면 서버가 시드만 보내도 모두 같은 층을 만들 수 있게 방·복도·배치가 한 함수에 모여 있다. 마을은 공유 공간, 집은 소유자만 바꾸는 개인 공간으로 나눈 것도 같은 이유다.

영역권장이유
클라이언트TypeScript + Phaser 3 (또는 PixiJS)타일맵, 아틀라스, 카메라, 입력이 내장되어 있고 픽셀아트 설정이 간단하다. 이 사이트의 다른 게임과 같은 엔진이다.
맵 제작TiledPhaser가 JSON을 바로 읽는다. 던전은 계속 코드로 생성한다.
멀티플레이Colyseus (Node.js, WebSocket)룸과 상태 동기화를 기본 제공해 소규모 협동에 맞는다.
저장·계정Supabase 또는 자체 Postgres멀티로 가면 브라우저 저장은 폐기한다.
배포정적 호스팅 + 별도 게임 서버클라이언트는 지금처럼 GitHub Pages, 서버는 Fly.io 같은 곳에 둔다.

06. 확인한 것과 하지 않은 것

확인한 것. 데스크톱 Chrome에서 키보드 이동, 나무·덤불 채집과 재생, 낚시 성공, 요리와 버프 적용(최대 HP 30→40), 가구 제작·설치·회수, 던전 생성(바닥 259칸, 광맥 9, 상자 3, 적 8)과 공격 피해, 사망 후 집에서 깨어나 저장되는 흐름을 실제로 실행해 확인했다. 390×844 세로 뷰포트에서 2배 배율로 그려지고 스틱과 버튼이 하단에 놓이는 것을 확인했다.

하지 않은 것. 실제 휴대폰 기기의 터치 지연, 성능, 배터리, 사파리 동작은 아직 보지 않았다. 재미와 수치 균형은 검증하지 않았고, 온라인 접속은 구현하지 않았다. 기획안의 공격 예고, 유물 전시, NPC 세 명, 첫 15분 튜토리얼은 이 시제품에 없다.
